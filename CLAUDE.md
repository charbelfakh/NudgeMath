# NudgeMath

You are a senior ML/full-stack developer.

## What this is
- A **math-hint generator** that nudges students toward the correct answer without revealing it, plus an **evaluation harness** that scores hint quality against pedagogical rubrics.
- **Contract-first**: shapes are defined once as Python dataclasses and propagated through typed boundaries — Python → Strawberry GraphQL SDL → codegen → TypeScript client. Shape drift is caught at build time, not runtime.
- Stack: Python 3.11 (hint logic + eval) · Strawberry GraphQL 0.319 + FastAPI 0.138 + Uvicorn (API) · Vite 8 + React 19 + TypeScript + Tailwind 4 + Apollo Client 4 + GraphQL Code Generator 7 (frontend).
- LLM access is **provider-agnostic and offline-by-default**: an `LLMClient` Protocol with one `OpenAICompatibleClient` (openai==2.43.0) pointed at Ollama by default (`llama3.2`, no API key), Anthropic's OpenAI-compatible endpoint, etc. Model + provider are **config from env vars**, never hardcoded.
- Human docs: `README.md` (setup/run), `docs/ARCHITECTURE.md` (contract-first design + boundaries), `docs/FIRST_EVAL.md` (first live eval writeup).

## Where things live
- Shapes (source of truth):  `hint_engine/models.py` — `HintRequest`, `Hint`, `Solution`, `TranscriptionResult`, `GeneratedProblem`, `EvalCase`, `ConversationTurn`, `CheckResult` dataclasses
- Generation (answer-blind):  `hint_engine/generate.py` — `generate_hint(HintRequest)`; system prompt + strict-JSON parse
- Image → text (answer-blind): `hint_engine/transcribe.py` — `transcribe_problem(image_data_url)` → `TranscriptionResult`; front-stage that feeds an ordinary `HintRequest` (transcribes, never solves)
- Vision interface:           `hint_engine/vision_client.py` — `VisionClient` Protocol + `OpenAICompatibleVisionClient` (image content part) + `ClaudeSubscriptionVisionClient` (subscription OAuth, Anthropic base64 image block; transcribes only); kept separate from `LLMClient` so the text path stays pure
- Curriculum taxonomy:        `hint_engine/curriculum.py` — loads `data/curriculum.jsonl` into `CURRICULUM`; `band_for_grade`, `default_template_topic`
- Problem generation:         `hint_engine/problem_gen.py` — `generate_problem(grade_level, topic?, difficulty?, mode)` → `GeneratedProblem`; `mode` = `template` (deterministic, exact answer, `verified=True`) / `llm` (`verified=False`) / `auto`. Template topics: `arithmetic`, `linear_equations`, `quadratics`, `geometry` (rectangles / Pythagorean / triangle area / angle sums — geometry is template in every band). Non-template topics (fractions, ratios, functions) fall to `llm` under `auto`.
- Solver (admin-only):        `hint_engine/solve.py` — `solve_problem(problem, grade_level?)` → `Solution`; a deliberate, auth-gated **solving** path (teacher tooling) on its own `get_solver_config()` model — never touches `generate_hint()` or any student-facing type
- Deterministic gates:        `hint_engine/evaluation.py` — five checks + `EvalReport` / `EvalReport.to_dict()` (the report envelope, and its source of truth)
- LLM-judge:                  `hint_engine/judge.py` — four-item rubric, `JudgeResult`, verdict logic
- Pre-LLM answer gating:      `hint_engine/answer_match.py` — `resolve_correct_answer`, `answers_equivalent`. Exact-only: rational values compare as `Fraction` (`1/2` ≡ `2/4` ≡ `0.5`), solution sets and systems compare order-insensitively; irrationals/percent/units fall back to string compare. **Never approximate** — a false "you're correct" is the failure that hurts; the supported classes are listed in the module docstring and pinned by a two-way test matrix
- Runtime admin state:        `hint_engine/runtime_settings.py` — `SETTINGS` (`RuntimeSettings`): one lock-guarded home for model overrides + Claude effort, with `reset()`. Per-process (N workers ⇒ N copies); `config.py` delegates to it
- Model/provider config:      `hint_engine/config.py` — `ModelConfig`, `LLM_GEN_*` / `LLM_JUDGE_*` / `LLM_SOLVER_*` resolution (`get_solver_config()` resolves independently of generation: override › `LLM_SOLVER_*` › provider default — switching one dropdown never moves the other), `COMPARISON_PRESETS`, `PINNED_COMPARISON_JUDGE`, `CLAUDE_SUBSCRIPTION` (generation/vision/solver preset). Model kinds: `vision` · `generation` · `solver`. `list_available_model_presets(kind)` filters `list_model_presets(kind)` by `is_config_available` (ollama always; API-key providers need their key env; `claude_subscription` needs OAuth sign-in) — the admin UI only lists available models.
- LLM interface:              `hint_engine/llm_client.py` — `LLMClient` Protocol + `OpenAICompatibleClient` + `ClaudeSubscriptionClient` (native Anthropic Messages API with the subscription OAuth bearer token + `oauth-2025-04-20` beta header + Claude-Code identity system block; answer-blind like every `LLMClient`)
- Claude subscription OAuth:  `hint_engine/claude_oauth.py` — in-app PKCE sign-in (`start_login`/`finish_login`/`valid_access_token`/`is_signed_in`/`logout`, auto-refresh); token stored at gitignored `.nudgemath/claude_oauth_tokens.json` (override `NUDGEMATH_CLAUDE_OAUTH_TOKENS_PATH`). No API key; personal-use only (relies on Claude-Code identity gating). Model via `CLAUDE_SUBSCRIPTION_MODEL`.
- Public-surface guards:      `hint_engine/rate_limit.py` — `RateLimiter` token bucket (thread-safe, LRU-bounded key set), `LLM_LIMITER` / `LOGIN_LIMITER`, `reset_all()`; per-process, disable with `NUDGEMATH_RATE_LIMIT=off`. `hint_engine/api/limits.py` — input ceilings (`MAX_IMAGE_CHARS`, `MAX_HISTORY_TURNS`, `MAX_PROBLEM_CHARS`, `MAX_REQUEST_BYTES`) + `check_length`/`check_image_data_url`/`check_history`
- Shared LLM utils:           `hint_engine/llm_utils.py` — `strip_code_fences`, `meta_from_config`, `parse_json_object` (strict-JSON reply → (dict, error), shared by generate/solve/problem_gen), `missing_api_key_error`, `MUST_PASS_RUBRIC`
- Seed cases:                 `hint_engine/data/eval_cases.jsonl` (dataset, one case per line) → loaded by `hint_engine/eval_cases.py` into `EVAL_CASES`; `EVAL_CASES[0]` is the canonical `algebra_sign_error` case (tests depend on this order)
- Curriculum data:            `hint_engine/data/curriculum.jsonl` (K-12 taxonomy, one topic per line) → loaded by `hint_engine/curriculum.py` into `CURRICULUM`; `template: true` topics have a deterministic generator
- CLI eval runner:            `hint_engine/run_eval.py` — `python -m hint_engine.run_eval [--judge] [--json PATH]`
- Cross-model comparison:     `hint_engine/model_comparison.py` — aggregation layer over `EvalReport` (does not reshape it)
- API:                        `hint_engine/api/schema.py` (**resolvers + schema assembly only**), `api/types.py` (Strawberry types + dataclass→GraphQL converters + `GENERATION_ROOT_TYPES`, which lives beside the types it names), `api/context.py` (`IsAdmin` permission, `client_key` rate-limit bucket), `api/limits.py` (input ceilings), `api/app.py` (FastAPI + CORS + GraphQL router; `get_context` resolves the `Authorization: Bearer` token into `admin_username`), `api/export_schema.py` (SDL export), `api/problem_store.py` (`PROBLEM_STORE` — `problemId` → answer store so practice answers stay server-side; pluggable `ProblemStore` Protocol, `InMemoryProblemStore` default / `RedisProblemStore` when `REDIS_URL` is set, chosen by `build_problem_store`). Mutations: `generateHint`, `transcribeProblem` (→ `TranscriptionType`, answer-blind), `generateProblem` (→ `GeneratedProblemType`; returns `problemId`, **no** answer), `evaluateCase` (**admin**; two LLM calls with `withJudge`), `login` (public, **rate-limited** → `AuthPayloadType`), `setModel(kind,preset)` (**admin**, runtime model override; rejects an unavailable preset), `startClaudeLogin` / `finishClaudeLogin(code)` / `disconnectClaudeSubscription` / `setClaudeEffort(effort?)` (**admin**, Claude-subscription connect flow + effort level → `ClaudeLoginStartType` / `ClaudeLoginResultType` / `ClaudeSubscriptionStatusType`), `solveProblem(problem, gradeLevel?)` (**admin** → `SolutionType`; worked solution via the separate **solver** model — off the generation path). Queries: `hints` (eval, answer-aware), `curriculum(gradeLevel?)` (→ `CurriculumTopicType`; band-scoped so the UI derives topic pickers), `revealAnswer(problemId)` (**admin** → `RevealedAnswerType`, reads `PROBLEM_STORE`), `adminModels` (**admin** → current models + **available** presets), `claudeSubscription` (**admin** → connection status)
- Auth / admin:               `hint_engine/auth.py` (stdlib scrypt `hash_password`/`verify_password`; HMAC-signed session tokens `create_token`/`verify_token`; secret from `NUDGEMATH_AUTH_SECRET`), `hint_engine/user_store.py` (`UserRecord` + `UserStore` Protocol, `FileUserStore` default / `InMemoryUserStore`, `build_user_store`, `USER_STORE`; accounts at `NUDGEMATH_USERS_PATH`, default gitignored `.nudgemath/users.json`), `hint_engine/manage_users.py` (`add`/`list`/`remove` CLI — bootstraps admins, no creds in code). Model switching lives in `config.py` (`set_model_override`/`clear_model_override`/`clear_overrides_for_provider`/`get_model_override`, `MODEL_PRESETS`, `list_model_presets`), which delegates the mutable state to `runtime_settings.SETTINGS` — lock-guarded, in-memory, **process-wide** (multi-worker deployments get one copy each), **override › env › default**. The **Claude subscription** connect flow (`hint_engine/claude_oauth.py`) is admin-only too: sign in once, then pick a Claude tier — `claude-sonnet-5` / `claude-opus-4-8` / `claude-haiku-4-5` (`CLAUDE_SUBSCRIPTION_PRESETS`) — per kind (shown only while signed in), plus a global **effort** level (`get_claude_effort`/`set_claude_effort`, `CLAUDE_EFFORT_LEVELS`, env default `CLAUDE_SUBSCRIPTION_EFFORT`; sent as `output_config.effort`, never for Haiku which rejects it); the OAuth token persists across restarts even though the model/effort overrides do not. `disconnectClaudeSubscription` forgets the token and drops any generation/vision/solver override that pointed at the subscription.
- Committed SDL:              `schema.graphql` (repo root) — the codegen source of truth (codegen reads the file, **not** the live endpoint)
- Frontend:                   `frontend/src/components/` — `HintView` (student, multi-turn: accumulates a `history` thread and sends it on follow-up attempts; **image drag-and-drop or file-pick** (PNG/JPEG/GIF/WebP/BMP, `ACCEPTED_IMAGE_TYPES`) → inline preview of the uploaded image (removable) → `transcribeProblem` → editable fields; takes optional seed props + `practiceMode` + `isAdmin` → shows the `SolveProblem` control for the current problem), `PracticeView` (grade / **band-scoped topic** / difficulty → `generateProblem` → embedded `HintView` seeded with the problem + its `problemId`; the answer is gated server-side and never reaches the client; the topic dropdown is driven by the `curriculum` query, not a hardcoded client list; takes `isAdmin` → shows `RevealAnswer` + `SolveProblem` controls), `SolveProblem` (admin worked-solution control via `solveProblem`; shows the solver model in a caption), `EvalView` (admin/portfolio), `AdminLogin` + `AdminPanel` (vision/generation/**solver** model switcher **+ Claude-subscription Connect/paste-code/Disconnect card with an Effort selector**, admin only; refetches `adminModels` on connect/disconnect so the dropdowns gain/drop the Claude tiers), `EvalReportCard`, `CheckResultRow`, `VerdictBadge`, `MathText` (renders problems/hints accurately: LaTeX via KaTeX + caret `^` superscripts, prose passed through); `src/auth/` (`AuthProvider`/`useAuth`, `tokenStore.ts`); `src/graphql/operations.graphql` (client ops); `src/generated/` (codegen output, committed); `src/apollo/client.ts` (bearer-token auth link). ## Commands
- Backend:        `uvicorn hint_engine.api.app:app --reload`  (GraphiQL at `http://127.0.0.1:8000/graphql`; CORS allows `http://localhost:5173`, override via `CORS_ALLOW_ORIGINS`)
- Frontend:       `cd frontend ; npm run dev`  (Vite on `http://localhost:5173`; first time `npm install`)
- Python tests:   `pytest -q`  (from repo root with the venv active; ~255 tests, all LLM/HTTP calls mocked; `tests/conftest.py` resets the process-wide rate-limit buckets + `SETTINGS` between tests)
- Lint:           `ruff check .`  (config in `ruff.toml`; `--fix` autofixes imports/ordering)
- Eval (CLI):     `python -m hint_engine.run_eval`  ·  `--judge` adds LLM-judge scoring (slower, real LLM) · `--json PATH` writes the per-case report envelopes as an artifact
- Comparison:     `python -m hint_engine.model_comparison --models llama3.2,sonnet-4.6 --judge`
- Admin accounts: `python -m hint_engine.manage_users add <username>` (prompts for password) · `list` · `remove <username>`. `start.ps1` auto-provisions a persistent `NUDGEMATH_AUTH_SECRET` in gitignored `.nudgemath/auth_secret` so sessions survive restarts (override via the env var; else a random per-process secret resets tokens on restart). Admin = teacher/portfolio superset of the student flow: reveal stored practice answers + generate worked solutions (separate solver model) + switch models; standard users need no login.
- SDL re-export:  `python -m hint_engine.api.export_schema > schema.graphql`  (**avoid** PowerShell `Out-File -Encoding utf8` — it writes a BOM that breaks the CI `diff`)
- Codegen:        `cd frontend ; npm run codegen`  (regenerates `src/generated/` from `schema.graphql`)
- Frontend build: `cd frontend ; npm run build`  (runs codegen → `tsc -b` → `vite build`)
- Frontend tests: `cd frontend ; npm test`  (Vitest + React Testing Library, mocked Apollo)
- Offline LLM:    `ollama pull llama3.2`  (default provider; no API key). Anthropic: `$env:LLM_DEFAULT_PROVIDER="anthropic"; $env:ANTHROPIC_API_KEY="..."`
- Claude subscription: no API key — Admin panel → **Connect** (opens claude.ai, paste the `code#state` back). Then pick a Claude tier (`claude-sonnet-5` / `claude-opus-4-8` / `claude-haiku-4-5` — all multimodal, so each is a Vision/Generation/Solver preset) and optionally an **Effort** level in the Claude card (`low`…`max`; default = API `high`; not sent for Haiku). Env: `CLAUDE_SUBSCRIPTION_MODEL` (**pins the model for all subscription presets when set** — leave unset to choose via dropdowns), `CLAUDE_SUBSCRIPTION_EFFORT` (effort default), `NUDGEMATH_CLAUDE_OAUTH_TOKENS_PATH` (token store, default gitignored `.nudgemath/claude_oauth_tokens.json`), `ANTHROPIC_BASE_URL`. Personal-use only (subscription tokens are gated to the Claude-Code identity); redistribute-facing deployments should use the API-key `anthropic` provider instead.
- Vision (photo → hint): default `llama3.2-vision` (text `llama3.2` is not multimodal). Override `LLM_VISION_MODEL` (e.g. `qwen3.5:9b` — accurate math OCR; `llava:7b` — reliable but weak) / `LLM_VISION_PROVIDER`. `get_vision_config()` resolves `LLM_VISION_*` in `config.py`. **Reasoning models**: Ollama clients send `reasoning_effort="none"` (see `_reasoning_effort_for`) or a thinking model (qwen3) burns its token budget reasoning and returns empty `content`. The Anthropic twin: `ClaudeSubscriptionClient` always sends `thinking` **explicitly** — `{"type": "disabled"}` by default, `{"type": "adaptive"}` when constructed with `thinking=True` (omitting the param means adaptive on Sonnet 5 but OFF on Opus, so explicit is the only way the solver's opt-in survives a model switch). Only the solver opts in (`client_from_config(..., max_tokens=4096, thinking=True)`), because a worked solution benefits from reasoning while hints/judge/transcription would get starved/truncated text. Transcription parsing (`transcribe._parse_transcription`) is deliberately tolerant — strips trailing commas, extracts an embedded JSON object, regex-grabs the `problem` field, and finally treats a plain-text reply as the problem (the student edits before requesting a hint).

## Conventions (these override casual prompt wording)
- **Never run `git commit` or `git push`** (nor `gh pr create`/merge) — the user owns all commits and pushes. Make and verify changes in the working tree only.
- **Never add AI attribution** — no `Co-Authored-By`, "Generated with", or any co-author/contributor trailer in commit messages, PR bodies, or anything you produce. The user is the sole author.
- **Never commit secrets** — API keys live only in env vars; provider config is `ModelConfig` resolved from the environment, never hardcoded values in code.
- **The answer-blind boundary is sacred.** `generate_hint()` takes only `HintRequest` and must **never** receive `correct_answer`. On the GraphQL generation path, the types in `GENERATION_ROOT_TYPES` (`HintRequestInput`, `HintType`, `HintMetaType`) must expose no answer field. `HintRequestInput.correctAnswer` exists for **teacher-side gating only** — used in the resolver *before* the LLM call, never forwarded to `generate_hint()`. Guarded by `tests/test_api.py::test_generation_path_has_no_correct_answer_on_output`.
  - **New front-stages keep the boundary.** `transcribe_problem()` only reads a problem (and any visible attempt) off an image — it never solves; `TranscriptionType` has no answer field (guarded by `test_transcription_type_has_no_correct_answer`). `generate_problem()` *knows* the answer (`GeneratedProblem.correct_answer`), but it is **never sent to the client**: the resolver stores it in `api/problem_store.py` (`PROBLEM_STORE`) and returns only an opaque `problemId`; `GeneratedProblemType` has **no** answer field (guarded by `test_generated_problem_type_has_no_answer_field`). `HintRequestInput.problemId` gates correctness server-side via `PROBLEM_STORE.get()` *before* the LLM call and is never forwarded to `generate_hint()` (guarded by `test_generate_hint_gates_correctness_via_problem_id`).
  - **Admin answer-reveal is a separate, auth-gated path — never a hole in the boundary.** `revealAnswer(problemId)` returns the stored practice answer on `RevealedAnswerType`, which is **not** in `GENERATION_ROOT_TYPES` and is unreachable from it (guarded by `test_reveal_answer_not_on_generation_path`); it requires the `IsAdmin` permission and reads the same `PROBLEM_STORE` — it never solves and never touches `generate_hint()`. Only known/stored answers are revealed (Practice mode); transcribed/typed problems have no stored answer. Admin is additive: it unlocks reveal + solve + `setModel` + the Claude-subscription connect flow, and takes nothing from the anonymous student flow.
  - **The admin solver is a second deliberate answer path, equally walled off.** `solveProblem(problem, gradeLevel?)` *does* solve — that is its purpose (teacher tooling: verify a model-authored problem, answer a photo problem with no stored answer) — but only behind `IsAdmin`, on the separate **solver** model (`get_solver_config()`), returning `SolutionType`, which is **not** in `GENERATION_ROOT_TYPES` and is unreachable from it (guarded by `test_solution_type_not_on_generation_path`). `solve.solve_problem()` never calls `generate_hint()` and its output never feeds the student hint flow or the `PROBLEM_STORE`.
  - **The Claude subscription is a provider swap, not a boundary hole.** `ClaudeSubscriptionClient` is an ordinary answer-blind `LLMClient` — it only relays the system + user prompts `generate_hint()` builds. The OAuth/status types (`ClaudeSubscriptionStatusType`, `ClaudeLoginStartType`, `ClaudeLoginResultType`) are admin config surface: **not** in `GENERATION_ROOT_TYPES` and unreachable from it (guarded by `test_claude_subscription_types_not_on_generation_path`). Sign-in only changes *which* model answers; it never touches correctness gating or the answer store.
- **Contract-first — Python is the source of truth.** Dataclasses in `hint_engine/models.py` and `EvalReport.to_dict()` define the shapes; GraphQL and TypeScript are *derived*, never the reverse. When you change the Python schema: (1) re-export `schema.graphql`, (2) `cd frontend ; npm run codegen`, (3) include the regenerated `schema.graphql` + `frontend/src/generated/` in the **same change**. `EvalReportType` mirrors `EvalReport.to_dict()` field-for-field (hint mirrored at report level as `hintText`/`revealsAnswer`/`meta`; no phantom top-level fields like `deterministicPassed`). Guarded by `test_api.py::test_eval_report_type_fields_match_to_dict_envelope` + the SDL-drift diff.
- **Two eval layers stay separate.** Deterministic gates (`evaluation.py`) are the hard, reproducible, CI-blocking invariants; the LLM-judge (`judge.py`) is advisory qualitative scoring (`MUST_PASS_RUBRIC` = `addresses_specific_error`, `no_semantic_answer_leak`). `deterministic.passed` blocks; root `passed` is the merged human-review verdict. Don't make the judge a build gate.
- **Comparison is an aggregation layer, not a reshape.** `EvalReport` is the per-(case, model) atom with unchanged fields/`to_dict()`. Never fold cross-model columns into `EvalReport` — group flat `list[EvalReport]` in `ComparisonTable` instead.
- **Tests ship with the change** — new module / env knob / gate / route needs a test in the same change; **mock the LLM** (`MockLLMClient`), never hit a live model in tests. Run `pytest -q` before calling work done.
- **The public surface is paid and unauthenticated — keep it bounded.** `generateHint` / `transcribeProblem` / `generateProblem` need no token and each spends a real model call (possibly on the admin's connected Claude subscription). Every new public resolver must (1) take `info: strawberry.Info` and call `LLM_LIMITER.check(_client_key(info), …)` before the LLM, and (2) size-cap its inputs via `api/limits.py` before doing work. `login` is rate-limited too — it is the one unauthenticated path that runs scrypt (~16 MB/attempt). Anything teacher-shaped (`evaluateCase`, `solveProblem`, `revealAnswer`, model/OAuth config) goes behind `IsAdmin` instead. Buckets are **per-process**: with N uvicorn workers the effective ceiling is N × the limit.
- **Error handling** — surface LLM/parse failures into `Hint.meta["error"]` / `JudgeResult.meta["error"]` (and the typed `meta.error` GraphQL field); don't silently swallow. **Truncation counts as a failure**: every client checks `finish_reason == "length"` / `stop_reason == "max_tokens"` and raises `llm_client.truncation_error(max_tokens)`, so a cut-off reply becomes one actionable message instead of a confusing JSON parse error (this is what a high Claude `effort` produces when thinking eats the budget). `MAX_HINT_CHARS` (600) is an unrelated *content* gate checked after the fact — see the comment on it in `evaluation.py`.
- **Deterministic invariants worth knowing**: `MAX_HINT_CHARS = 600`; banned phrases in `evaluation.BANNED_PHRASES`; pure-digit answers are matched on word boundaries with positional phrases ignored (`_POSITIONAL_PREFIX` — "step 7" is not a leak), while tiny numbers 1–5 fall back to substring; a case may opt out of a named gate via `expectations["skip_checks"]` (default: all 5 run).
